An 8-bit processor that can tell when its own software has hung

DSD-8 is a Harvard-architecture processor written in Verilog for the Digital System Design course. Our add-ons are a hardware watchdog timer and a 16-bit timer. Try the watchdog below.

What the project is

DSD-8 fetches 16-bit instructions from a 512-word instruction memory (9-bit address) and works on 8-bit data with eight registers, R0 to R7. It has 16 opcodes: NOP LDI LD ST ADD SUB AND OR XOR SHL SHR CMP JMP IN OUT HLT, plus eight conditional branches (BEQ BNE BCS BCC BMI BPL BVS BVC). IN and OUT talk to peripherals through an 8-bit port address.

Every peripheral sits behind io_bus.v, which decodes the port and returns io_ready.

Watchdog timer implemented and tested

Firmware must write the key 0xA5 to WD_KICK before the counter reaches zero. If it doesn’t, the watchdog sets a sticky expired flag, lights LED 7 in hardware, and can reset the CPU. Any other value written to WD_KICK is ignored, so runaway code is unlikely to keep it alive by accident.

timeout (clocks) = (WD_RELOAD + 1) × (WD_PRESC + 1)
PortRegisterAccessMeaning
0x50WD_CTRLR/Wbit 0 enable, bit 1 reset CPU on expiry
0x51WD_RELOADR/Wvalue the down counter restarts from
0x52WD_PRESCR/Wcounter steps once every PRESC + 1 clocks
0x53WD_KICKWwrite 0xA5 to reload counter and prescaler
0x54WD_STATUSR/Wbit 0 expired (sticky), bit 1 enabled. Any write clears the flag
0x55WD_COUNTRcurrent down-counter value

Design rules worth knowing

A kick and a timeout in the same clock cycle: the kick wins. The reset request is a one-cycle pulse, merged in the top level as cpu_rst_n = rst_n & ~wd_reset_req. The watchdog itself is reset only by rst_n, so the expired flag survives the CPU reset it causes and the boot code can read why it restarted.

16-bit timer in progress

The repository’s rtl/timer.v is a working 8-bit timer: port 0x30 reads the count, port 0x31 sets enable (bit 0) and clear (bit 1), and an overflow pulse fires on wrap from 0xFF. tb_timer.v tests it on its own. The 16-bit version extends this to a 16-bit counter read as two bytes, because the data bus is only 8 bits wide.

Demo programs

Both run on the processor and are checked against the golden reference simulator (tools/dsd8sim.py).

Healthy: firmware keeps kicking

; timeout = (15+1)*(3+1) = 64 clocks
LDI R4, 15
OUT 0x51, R4
LDI R4, 3
OUT 0x52, R4
LDI R4, 1
OUT 0x50, R4   ; enable
LDI R3, 0xA5
LDI R2, 1
LDI R1, 5
LOOP: OUT 0x53, R3  ; kick
SUB R1, R1, R2
BNE LOOP
IN  R7, 0x54   ; R7 = 0x02
HLT

LED 7 stays off.

Hung: nobody kicks

; timeout = (2+1)*(1+1) = 6 clocks
LDI R4, 2
OUT 0x51, R4
LDI R4, 1
OUT 0x52, R4
OUT 0x50, R4   ; enable
LDI R3, 0xA5
OUT 0x53, R3   ; one kick
LDI R1, 20
LDI R2, 1
HANG: SUB R1, R1, R2
BNE HANG       ; never kicks
IN  R7, 0x54   ; R7 = 0x03
HLT

LED 7 turns on and the flag reads expired.

Verification

The testbench in tb/tb_dsd8.v prints one trace line per retired instruction. scripts/run_conformance.py diffs it against the golden trace from the reference simulator and reports the first differing line.

The watchdog has its own self-checking testbench, tb_watchdog_timer.v, covering reset state, enable and disable, reload, prescaler, exact timeout length, valid and invalid kick keys, the sticky flag, flag clearing, the one-cycle reset pulse, readback, and the kick-versus-expiry tie. tb_dsd8_top_watchdog.v tests it again with the whole processor.
